# Native FOMC lexical novelty: source feasibility audit

Audit scope: accepted source tree identified by parent as main `e574f4622639b09517ce7ee51c8eb536a7ede2cd` / tree `73f9496465c78938260322a93db9c55a0415b50a`. Read-only source inspection; no tests, network, runtime initialization, refresh, or product changes. This note is a feasibility checkpoint, not implementation approval or proof of real observations.

**Conclusion:** a deterministic, prospective comparison of two already stored normalized FOMC texts is feasible without new acquisition or LLM work. The existing APIs do not yet provide the required received, exact-linked text pair or fresh-event admission. A small bounded native pair reader plus a scoped lexical proof is the honest next increment. Do not relabel `macro.fomc_statement_change` or the historical T0 overlay as that producer.

## Source and actual call path

* `seiltanzer/macro_fomc_deterministic_bootstrap.py:314-336` stores immutable `release_id`, dated URL, parsed `published_at`, first `fetched_at`, normalized `body_text`, its full SHA256, exact `previous_release_id`/URL, contract, and local `created_ts`. `ingest(spec, *, html, previous_source_url=None, fetched_at=None)` is at :361-406. Duplicate `(source_url,body_sha256)` returns cached without updating the first fetch (:383-400).
* `extract_statement_text` (`seiltanzer/fomc_official_source.py:76-111`) selects text after the release-time line and before explicit footer markers, preserving the initial economic paragraph; HTML is normalized, not retained in this store. `_normalize_text` enforces 80..30,000 characters (`macro_data_factory.py:26-27,70-84`). These are normalized-document hashes, not raw HTML response hashes or original-publication vintage proof. Missing footer/layout changes can leave extra text in a body; do not silently improve historical normalization under the same contract.
* Timestamp comes from the statement's own release line and timezone validation (`macro_fomc_deterministic_bootstrap.py:172-188`). The dated URL/spec supplies the date. Native base archive returns actual HTTP completion time (:573-581).
* Production installation uses `StrictFOMCDeterministicReleaseStore` (`macro_data_factory_routes.py:115-127`); strict ingestion only requires the requested previous URL to exist (`macro_fomc_deterministic_store_refinement.py:24-31`). `_previous` chooses the earliest locally created version at that URL, validates only publication order, and freezes its exact ID (:345-374). Do not replace that link with whichever previous row happens to be latest later.
* Crucially, production installs `install_historical_offhost_transport()` first (`macro_data_factory_routes.py:92-94`). It replaces `FOMCDeterministicBootstrapRuntime.refresh` with the verified local bundle reader (`macro_historical_offhost_bundle.py:968-1016`), not the apparent hourly Fed GET materializer. `_fomc_refresh` reads the bundle, skips existing URLs, and ingests stored HTML with the **offhost HTTP** `record['fetched_at']` (:893-965). Bundle generation fetches statements oldest first and retains predecessor URL, raw HTML hash and fetched time (:332-369). No existing bridge copies `macro_documents` ingestion into this deterministic store.
* Separate `FOMCOfficialRuntime` starts with 120-second delay, then polls hourly (`macro_fomc_runtime.py:20-25,46-76`; routes :121,147). `refresh_latest_fomc` fetches two statements, seeds previous raw text, and extracts latest with the guarded LLM (`fomc_official_source.py:204-218`). Its `macro_documents` table is immutable and keeps first text/fetch/hash (`macro_data_factory.py:225-267,343-353`), but has no exact previous document ID link. The previous-text query is publication ordered without receipt filtering (:269-276). This semantic path is unsuitable as an already-proven no-LLM event novelty producer; do not trigger it for novelty.

## Receipt and liveness gaps

* Existing `latest_received(captured_ts, *, nonblocking=False)` (:411-421) invokes `_latest_release(..., received_only=True)` (:454-493): current publication <= HTTP fetched_at <= capture; nonblocking lock supported. It returns metadata and historical payload, **not body_text or previous row receipts**. `latest_admissible`, the deterministic T0 context (`macro_t0_context.py:87-143`), and historical feature overlay (:496-537) deliberately admit by publication only. Preserve those meanings; add a distinct prospective reader.
* Offhost fetched_at can precede local import. Local `created_ts` is recorded at insertion (:398-400), while `latest_received` ignores it. For honest local known-at-capture replay, require **both** fetched_at and first local created_ts <= capture for each linked row; keep both clocks and set prospective available_at to their maximum. HTTP first receipt alone is not proof that the production process held the text before capture. This is particularly material for a later installed bundle.
* Pair reader must fetch current row + exact `previous_release_id` under one bounded/nonblocking lock; validate both full stored body hashes, nonempty bodies, official identity, previous publication < current publication, and both received/materialized clocks. Missing link, future previous receipt, malformed body/hash or busy store must be unavailable, with a precise reason. Ingest currently tolerates fetched_at up to 300 seconds before publication (:379-381); prospective pair must reject any fetched_at < publication, as the current received reader already does.
* Neither latest_received nor the historical T0 context imposes event age. A freshly imported old statement is still old. Gate event freshness by **current publication**, never by fetch/import time; declare a finite age window in the new contract and fail closed outside it. Retain current release ID as dependence unit across repeated T0s; duplicate reads/receipts must not create new events or increase independent n. Do not skip a newer inadmissible publication to manufacture a fresh comparison using an older pair.
* Mutable URL concerns: direct ingest can append a new body/hash at the same dated URL; current reader chooses newest created version at equal publication (:467), while predecessor selection chooses earliest (:352). Automatic base and offhost materializers skip any already stored source URL (:653-656; offhost :925-927), so they do not track revisions. First stored receipt is not cryptographic first-publication vintage; preserve `historical_reconstruction=True` and `OFFICIAL_DATED_PAGE_NOT_VERSIONED`. A new version at an old URL must not renew publication time or event freshness, and must not silently count as another policy event.
* Configured deterministic worker has 150-second startup and hourly poll (`macro_fomc_deterministic_bootstrap.py:592-597,688-693`), including after refresh monkeypatch. The source comment about daily historical checks (`routes:144-145`) does not alter those defaults. The visible offhost workflow is `.github/workflows/production-ede-v12-audit.yml:12-14,70-89`: daily 01:17 UTC build/install, plus explicit dispatch. Bundle validation requires exact runtime SHA and default 45-minute/max 60-minute age (`macro_historical_offhost_bundle.py:27-41,462-484,780-791`). Thus hourly local refresh + daily offhost generation is not a prompt native statement feed; an offhost receipt normally arrives long after a short event window, and a poll can miss the brief valid bundle interval. Real worker status, current latest statement, actual refresh timestamps, bundle existence and paired rows are **not established** here: no bounded actual runtime DB/bundle was found among the inspected workspace file names. Source behavior and mocked tests cannot establish live freshness.

## Smallest honest proof and bounds

1. Read existing bodies with explicit source-text bounds (stored bodies are <=30,000 characters; cap UTF-8 bytes too), and validate whole normalized-document SHA256 before extracting. No fresh GET, extraction call, dependencies, guessed sentences, or historical availability reconstruction.
2. Prefer a **fixed-scope exact target-rate decision sentence** for a first bounded proof: require one unambiguous sentence containing a Committee decision and the target-range anchor already supported by `_TARGET_RANGE_RE` (:70-78,211-219). Retain exact original normalized sentence bytes and offsets, both full document hashes/IDs/URLs/publication/HTTP receipt/local materialization clocks, selector/tokenizer version, and scope. Do not merely regex the numeric range and call it the full decision sentence. Decimal periods must not split a sentence; reject ambiguous, absent, multiple decision matches, incomplete terminator or unsupported layouts rather than synthesizing text. The fixtures show this region is source-supported, but no actual production pair was inspected to prove its presence.
3. Deterministic lexical difference can be unsigned token-set Jaccard distance (0 identical sets, 1 disjoint) or another explicitly versioned token rule; preserve exact scoped snippets so normalization/tokens can be reproduced. This measures **decision-sentence lexical difference**, not semantic surprise or whole-statement novelty. No rate/action sentiment sign, forecast, profit estimate, risk command or model promotion follows from it.
4. Check the **entire serialized extension/proof <=4096 UTF-8 bytes**, not just text/token lengths, at producer and admission. Set per-snippet/identity/token-count bounds with margin for two complete document provenance records; reject the whole proof when it exceeds budget. Never slice text or retain only the first N tokens and claim complete comparison. Existing event reaction uses separate 4096-byte extension/root limits (`edge_family_event_reaction.py:21-23,58-81`); selected source families share an 8000-byte review budget (`edge_family_source_runtime.py:21`, reaction :385-388). Respect both when combining novelty with reaction facts.
5. Whole-statement sorted unique token projection would capture economic outlook, guidance and voting language that this sentence omits. It can be more meaningful if **complete** token projections plus both provenance records fit 4096B for an actual pair, with a fixed whole-statement contract and oversized pairs rejected. Existing source only guarantees <=30,000 characters, not <=4096B proof. No actual local pair proves the whole projection fits; do not assert it does or change scope based on fit under one feature name. A sentence contract first is defensible; whole-statement contract later requires concrete size evidence.

## Existing test evidence and next increment

Read, not executed: `tests/test_macro_fomc_deterministic_bootstrap.py:64-77` specifies first-fetch preservation and distinguishes reconstruction from received admission; :124-138 requires a materialized predecessor; :141-174 checks exact link, immutable rows and historical publication admission. `tests/test_fomc_official_source.py:50-71` covers canonical body boundaries/initial paragraph; :74-128 uses fake documents and extractor. These do not cover received pair admission, local offhost-import receipt, freshness, ambiguous sentence selection, changing vintages or proof byte budgets and are not real observation evidence.

Recommended next increment: a separate fail-closed bounded store pair-reader and versioned decision-sentence lexical proof, attached prospectively through the existing event source capture/admission path. Preserve all full-document provenance, enforce publication age and both rows' HTTP/local availability, and provide explicit unavailable reasons. This increment can supply genuine lexical measurements **when a qualifying pair exists**. It cannot claim a live working source now or completion of plan §7's predictive event edge (`docs/TRADING_DBD_UNIFIED_EDGE_PLAN_2026-10-01.md:114,122`); the visible offhost cadence is a concrete liveness blocker for timely event coverage. Improving acquisition/cadence or bridging semantic-path ingestion is separate scope, not authorized by this source audit.
