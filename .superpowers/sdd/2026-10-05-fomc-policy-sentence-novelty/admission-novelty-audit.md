## Minimal design

1. Introduce one versioned, deterministic lexical novelty producer/validator with a reserved exact feature namespace (for example `event.fomc.lexical_novelty_*`), explicit units (dimensionless ratios/counts as specified), extraction-region identifier and tokenizer/metric version. Metric and region are fixed before observation; no sentiment score, fixed action sign, embeddings, LLM or calibrated-effect claim. Do not feed generic `source['features']` through `_fact_features` to admit novelty.
2. A small received linked-pair reader returns the actual current and its stored `previous_release_id` row, with original IDs, URLs, normalized body hashes, publication and first-receipt clocks. It must retain link identity and verify chronological order/known-at-capture receipt on both supports. This is an integration gap, not a source assessment: `macro_fomc_deterministic_bootstrap.py:411-421` exposes a nonblocking current read; `_latest_release` at 464-492 returns current hash/payload/link but no text or previous receipt/hash. `_previous` at 345-359 also lacks prior receipt/hash and selects by URL. Do not derive novelty from the existing deterministic payload or replace the stored link with “latest earlier release.”
3. Capture a bounded, frozen projection of the fixed extraction region from both actual stored texts. Retain original normalized-document hash identity separately from a digest of the precisely specified retained projection. The projection must be independently sufficient to recompute every admitted lexical metric; neither metrics nor projected digests alone constitute proof. Bound source-text work before copying/tokenization (including SQL materialization); output-size limits alone do not bound work on a huge stored body. Reject an oversized/unavailable pair explicitly; do not dynamically shrink the region to fit existing facts.
4. Proof ≤4096B includes both support identities/clocks/hash kinds, link, region and metric contract, projection bytes and digests. Total serialized selected sources remains ≤8000B with existing facts first. Producer reads/validates originals before projecting; trainer revalidates the frozen supports, digest formats/bases, retained projection digests, metric units/value, exact metadata, root/support identity/link, scope, synthetic flags, positive clock ordering, cutoff, freshness, depth and byte bounds. Bind each support ID to one canonical proof within a row; also prevent contradictory release support across novelty and reaction when they share an ID.
5. Add all-or-none extension validation at adapter and source-runtime boundaries. No recognized extension fields means the legacy surprise/reaction behavior is preserved. Any recognized novelty field present with null/partial/unknown version, unknown proof fields, malformed projection, mismatch or forged aggregate rejects that record before surprise/reaction/novelty feature insertion. Exact reserved namespace and explicit metadata dispatch must also fail closed in the trainer; a renamed feature with novelty metadata cannot become ordinary consensus-backed event data. An invalid record does not remove other already admitted source records.

## Capture recommendation and specific pitfalls

**Use the existing single optional capture owner and its same total 0.25s budget.** `edge_family_event_reaction.py:459-523` starts the deadline before private input copying, submits on the default executor, shields the worker, checks timely completion before commit, and keeps engine admission held until running work actually exits. `:405-456` copies only bounded JSON input; `:351-393` preserves existing source facts and refuses an over-budget append. Extend this owner to two independent producer outcomes/audits and one private result commit. Read the received release/pair once where practical; novelty must succeed without supported price identity, feed locks or completed reaction bars. Preserve the existing reaction producer/validator and feed bound (`:261-348`).

Do not chain novelty after the existing reaction-success return: reaction is unavailable for many instruments/window states, while text novelty is an independent observation. Conversely, a novelty refusal must not overwrite successful reaction facts. Current commit is gated on reaction audit `available` at 508-511; a coupled capture needs a source-change/individual-results commit decision so novelty-only success can commit. Preserve timely-only rights, cancellation propagation, lock release, executor queue accounting and no overlap with a surviving worker. A second independent executor task or second 0.25s API wait broadens latency and overlap; avoid it. If fixed bounded pair work cannot fit, prepare/cache it during existing ingestion/off-host work and let this same bounded capture read the frozen result; do not enlarge the budget or add HTTP/archive/provider work.

The current reaction `_bounded` strings are limited to 128B except URLs/dependency groups (`:58-75`); do not reuse that policy unchanged for retained text. Give only the explicit projection-text field its own small cap, retaining depth and total bytes. Existing serializers differ: source runtime and merge use ASCII/default JSON (`source_runtime.py:123`, `event_reaction.py:387`), while compact roots use compact UTF-8 (`operational_edge_compaction.py:38-41`). Enforce the existing conservative selected-source representation as well as the proof cap, including escaping and retained preexisting facts; never evict old facts to fit novelty. `_attach_family_source_bundle` deduplicates by source ID but does not bound its merged total (`app.py:277-317`), so novelty append must check the complete already-merged root as reaction currently does.

**Hash limit:** a short region/token projection cannot reconstruct a full original normalized-document SHA256. Preserve that original digest as lineage and validate it at the actual store reader; independently recompute a clearly named projection hash in frozen replay/training. A self-contained digest plus `source_verified=True` cannot authenticate an arbitrary wholly forged original document. Do not claim the trainer verifies the original full-body hash from a snippet. If the contract requires that stronger guarantee, retain both whole originals only when the proof cap permits, or supply a separately authenticated immutable original-source manifest; it cannot be achieved by relabeling the projection hash.

Same-release dependency lineage is essential but not magical: pool deduplication keys the complete evidence-family tuple and action set (`adapters.py:598`); partially overlapping family sets are not exact duplicates. Keep novelty in the existing event model/family forecast rather than inventing a second novelty component, and preserve the current shared-source dependence handling across pools. Trainer independence currently groups by `trade_id` (`training.py:352-360`); many trades exposed to one FOMC release are not independent release observations. Do not report such trades as a sufficient independent FOMC-event cohort or relax unchanged sample/OOS gates to activate a model.

`context_only=True` has a precise exclusion meaning in `_source_declaration_reason` (`dataset.py:69-72`), trainer (`training.py:196-197,272`) and applicability (`adapters.py:451-452`). Describe admissible lexical evidence as observed text context with no causal-effect/broker/outcome authority; do not set that exclusion flag and then bypass it to train. Explicit context-only inputs remain excluded.

No model means zero vote (`adapters.py:76-84,466-585`); novelty availability must not imply surprise computed, validated action forecast or economic authority. Preserve action identity/geometry, proof, costs, 32-feature cap, purge, ≥20 training groups/20 validation groups, two untouched blocks and positive OOS gain (`training.py:26-31,257-264,350-424`; runtime model admission `adapters.py:483-499`). Risk/cost/provider/acceptance/smoke gates and broker/outcome semantics remain unchanged. No empirical efficacy is established by this audit.
