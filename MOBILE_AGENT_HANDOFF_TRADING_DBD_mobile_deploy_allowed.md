Дата среза: 4 августа 2026. Этот документ можно целиком передать следующему ИИ-агенту.

## 1. Твоя роль и жёсткая граница задачи

Ты продолжаешь проект **только как агент мобильного интерфейса**. Твоя задача — сделать существующий терминал удобным и читаемым на телефоне, не меняя его торговую логику, данные, математику, сервер и десктопный образ.

Разрешено:

- responsive CSS, сетки, размеры, отступы, типографика;
- мобильная компоновка карточек, шапки, кнопок, форм и модальных окон;
- touch-targets, горизонтальный/вертикальный overflow;
- высота и ширина контейнеров canvas/Plotly/ECharts на разных экранах;
- безопасный вызов resize/reflow графиков при изменении viewport/orientation;
- touch-взаимодействие с 3D-моделями при сохранении текущей камеры;
- доступность и читаемость, не меняющие значения показателей.

Запрещено без отдельного письменного разрешения владельца:

- менять Python, API, базу, торговую математику и формулы вероятностей;
- менять алгоритмы визуальных моделей, содержимое метрик или их интерпретацию;
- менять источники котировок, символы, basis mapping, WebSocket/REST fallback;
- менять AI verdict, его prompt, OpenRouter или прокси;
- менять файлы GitHub Actions, deploy-скрипты, systemd, secrets и серверную конфигурацию;
- прямо редактировать production-сервер по SSH или вручную менять `/opt/seiltanzer`;
- переносить/восстанавливать старые коммиты целиком поверх актуального кода.

После успешных тестов и проверки diff разрешено:

- создать PR мобильной ветки в `main`;
- выполнить squash merge в `main`;
- запустить существующий штатный GitHub Actions автодеплой;
- проверить production HEAD, статус сервиса и HTTP 200.

Не изменяй сам workflow деплоя. Используй только уже существующий процесс.

Если мобильная проблема требует изменения защищённого слоя — остановись, опиши симптом, файл, предполагаемую причину и минимальный контракт изменения. Само изменение не делай.

## 3. Как начать без рассинхронизации

Сначала ничего не редактируй. Выполни и пришли владельцу вывод:

```bash
git status -sb
git remote -v
git fetch origin
git rev-parse origin/main
git log -1 --oneline origin/main
```

Если рабочее дерево грязное, не делай reset/pull/checkout поверх изменений. Сначала сохрани локальную работу в отдельную backup-ветку/коммит или покажи `git diff --stat` владельцу.

Для чистого старта:

```bash
git switch -c agent/mobile-ui 466d17ca6a0210d103f4b465406e1f704c36bc03
```

Если ветка уже существует, создай новую с датой/суффиксом. Все мобильные изменения должны остаться в этой ветке. В конце — commit + diff/PR. После успешных тестов разрешено выполнить **squash merge в `main` и штатный автодеплой**.

Перед началом обязательно зафиксируй базу для отката:

```bash
BASELINE_SHA=466d17ca6a0210d103f4b465406e1f704c36bc03
git show -s --oneline "$BASELINE_SHA"
```

Финальный мобильный commit должен быть явно помечен:

- commit title: `feat(mobile): responsive terminal UI`;
- после merge записать полный deployed SHA;
- создать annotated tag вида `mobile-ui-2026-08-04` на фактически задеплоенном commit;
- в итоговом отчёте указать baseline SHA, PR, merge SHA, tag и deploy run.

Пример маркировки:

```bash
git tag -a mobile-ui-2026-08-04 <DEPLOYED_SHA> -m "Mobile UI release based on 466d17c"
git push origin mobile-ui-2026-08-04
```

Если после деплоя обнаружена регрессия, не делай force-push и не переписывай историю. Создай отдельный rollback commit через `git revert <DEPLOYED_SHA>` или revert PR в GitHub, снова прогони тесты и задеплой штатным workflow.


## 4. Что это за продукт

SEILTANZER TERMINAL — визуальный терминал сопровождения уже открытой дискреционной сделки. Он не является сигнальным сервисом. Пользователь знает сетап при входе; во время сделки терминал показывает динамику цены, опционную геометрию, вероятностные сценарии, время, уровни и состояние позиции.

Ключевая эстетика и смысл: «бумажный» профессиональный квант-терминал, IBM Plex Mono, компактность, динамические canvas/3D-визуализации. Мобильная версия не должна превращать его в набор примитивных таблиц и не должна удалять визуальные модели. На телефоне допускается вертикальный поток панелей и управляемый горизонтальный скролл там, где уменьшение уничтожает смысл.

Основные визуальные модули, которые обязаны остаться:

1. `PROBABILITY LATTICE · ЖИВАЯ ДОСКА ГАЛЬТОНА`
2. `STRIKE LANDSCAPE · ГРЯДА RISK-NEUTRAL ПЛОТНОСТЕЙ`
3. `OI × GAMMA CONTEXT · ЭВОЛЮЦИЯ УСЛОВНЫХ УРОВНЕЙ`
4. `PROBABILITY CONE · КОНУС ВЕРОЯТНОСТИ (3D)`
5. `ВЕЕР ВЕРОЯТНОСТИ · 2D` — расположен внутри панели конуса
6. `IV SURFACE · ПОВЕРХНОСТЬ ВОЛАТИЛЬНОСТИ (3D)`
7. `КАРТА УРОВНЕЙ · КОРИДОР ЦЕНЫ`
8. фильтры стратегии и лестница фиксаций
9. `CROSS-ASSET CORRELATION · МАТРИЦА СВЯЗЕЙ`
10. журнал сделок, AI-разбор и история AI-разборов.

## 5. Защищённая логика, которую нельзя «улучшать» в мобильной задаче

- Вероятности TAKE/STOP/NO-TOUCH считаются option-anchored finite-horizon first-touch моделью, а не пропорцией расстояний до стопа/тейка.
- NO-TOUCH — отдельная масса сценариев, а не вероятность стопа.
- Risk-neutral density, IV/skew/term и live mapping уже используются сервером и JS.
- OI/GEX — эвристический контекст, не авторитетная вероятность.
- Значения меньше разрешения интерфейс показывает честно (`<0.1%`), а не подменяет нулём.
- Лестница менеджмента: частичная фиксация 10% на 1R, 1.25R, 1.5R, 1.75R, 2R, 2.2R; BE/trailing только после 1.5R.
- AI анализирует option/RND/IV/skew/term, live tape/ATR/levels, correlations, OI/GEX, время и качество данных; текущий формат человекочитаемый и не должен меняться мобильным агентом.
- Котировки имеют настроенное соответствие брокерным инструментам и устойчивую basis-привязку. NAS100, XAU и остальные mapping/fallback не менять.

## 7. Важные правила для графиков на мобильном

1. 3D-камера конуса и IV surface после жеста должна оставаться там, где пользователь отпустил палец. Live-render, resize и orientation change не должны сбрасывать её в исходное положение.
2. Не вызывать полный `newPlot` на каждом resize, если это сбрасывает `scene.camera`; сохранять `relayoutData.scene.camera`/текущий camera state и использовать `uirevision`/react согласно существующей реализации.
3. Touch-жест внутри 3D должен управлять моделью, а не одновременно прокручивать всю страницу. Но обычная вертикальная прокрутка вне plot должна оставаться естественной.
4. Canvas должен учитывать `devicePixelRatio`, иначе подписи и линии на Retina будут размыты. Не менять координатную математику данных — только backing size/render scaling.
5. ECharts уже использует `ResizeObserver` в `gex.js` и `correlation.js`; не создавать бесконечные циклы resize.
6. Для графика лучше минимальная практическая высота и горизонтальный контейнер, чем сильное сплющивание. Не обрезать подписи стопа/входа/тейка, P10/P50/P90, mode, шкалу времени/развязки.
7. Никаких визуально «красивых» фейковых шариков/линий, если они не связаны с текущими данными. Анимации обязаны сохранять смысл.

## 8. Мобильная цель по зонам

### Шапка и состояние

- На 320–430px бренд, фиды, часы и кнопки не должны вылезать за экран.
- Основное действие `НОВАЯ СДЕЛКА`/`ИИ · РАЗБОР СДЕЛКИ` доступно без микроскопического текста.
- Feed status можно переносить строками, но нельзя скрывать качество данных.
- Карточки состояния должны читаться как 2 колонки или горизонтальный snap-scroll; `ЧТО ДЕЛАТЬ` — на всю ширину.

### Панели

- Заголовок, badge и кнопки переносятся без наложений.
- Stats-column на телефоне идёт над визуализацией, но не занимает весь первый экран; допустим компактный grid/раскрытие вторичных строк.
- Tooltip на touch не должен блокировать скролл навсегда.
- Footnote остаётся доступным, но может быть сворачиваемым только через presentation-only механику.

### Формы и модальные окна

- Все inputs/select/textarea минимум 16px по размеру шрифта на iOS, чтобы Safari не zoom-ил форму.
- Touch target кнопок ориентир 44×44px, между опасными действиями есть расстояние.
- Modal помещается в `100dvh`, внутреннее содержимое прокручивается; кнопка закрытия всегда доступна.
- Клавиатура не должна скрывать кнопки сохранения.

### Таблицы и журнал

- Не сжимать финансовые числа до нечитаемости. Использовать внутренний горизонтальный scroll с явным визуальным намёком.
- Закреплённая первая колонка допустима, если не ломает desktop.

## 9. Критерии приёмки

Проверить ширины: 320, 360, 390, 430, 768px; отдельно landscape 667×375 и 844×390. Проверить desktop минимум 1366×768 и 1920×1080.

На каждой мобильной ширине:

- нет горизонтального scroll у всей страницы; он допустим только внутри специально отмеченных графиков/таблиц;
- текст, цены и статусы не перекрываются;
- все кнопки нажимаются пальцем;
- новая сделка, закрытие, AI modal/history и журнал доступны;
- live-тики не вызывают прыжков высоты/скролла;
- lattice, ridge, GEX, cone+fan, IV surface, levels и correlation видимы и не белые;
- 3D можно вращать пальцем, и камера не возвращается после отпускания и следующего тика;
- после portrait ↔ landscape графики корректно занимают контейнер и сохраняют камеру;
- десктопный вид визуально не регрессировал.

## 12. Что уже исправлено и нельзя случайно откатить

- котировки и basis mapping больше не должны резко перескакивать между разными шкалами;
- XAU/NAS100 и другие инструменты имеют настроенные источники/fallback;
