# Mathematical edge: рабочая версия для личного терминала

Price-модели уже участвуют в ручном менеджменте. Это ограниченное влияние исторической модели, а не сертификат прибыли. Научные prospective требования из архива не блокируют личное использование рабочей версии.

## Что считает модель

Для каждого из десяти инструментов отдельно выбирается горизонт 15/30/60 минут. Признаки: signed и absolute returns за 5/15/30 минут, return 60 минут, RMS volatility за 15/30/60 минут, положение в часовом диапазоне и время UTC. Берутся только 13 завершённых последовательных пятиминутных баров; runtime агрегирует их из пяти полных минутных баров каждый.

Две logistic головы с фиксированной регуляризацией L2=10:

- `P(move)`: абсолютное изменение log-price больше 0.0002, примерно 2 bp.
- `P(up | move)`: направление **только при таком движении**. Нулевой/незначительный исход не считается падением.

Это новая рабочая спецификация. Она использует идею и семейства признаков из исследования, но не притворяется восстановленным старым Price decoder. Target contract хранится в каждом модели и проверяется при загрузке.

Веса для позиции: `d = sign(position) × (2P(up|move)−1) × P(move)`. Модель с подтверждённой direction головой может менять мягкое ранжирование HOLD/CLOSE_10/CLOSE_25/CLOSE_50/EXIT. Если подтверждена только movement голова, снижение P(move) может менять ранжирование уже допущенных TIME_STOP/REDUCE_TAKE; оно не создаёт направление или команду CLOSE/EXIT.

## Веса и ограничения

Максимум математического компонента — 15%; Active Edge, исторические LLM-гипотезы и математический компонент делят существующий бюджет 40%. Вес уменьшается с proper-score gain, согласованностью временных блоков, размером финального теста, возрастом обучающих данных и силой текущего сигнала. Старше 90 дней вес данных равен нулю. Артефакт обновляется ежедневно и после деплоя, срок его использования — семь дней, только для exact runtime SHA.

Для базовых политик bounded blend действует внутри hard CVaR допуска. При математическом вмешательстве выбранная политика не может проигрывать лучшему исходному net Expected больше существующей зоны 0.03R. Исходные Expected, медиана, CVaR, пути симуляции и размер позиции не переписываются. В отчёте значение мягкого ранжирования не называется прибылью.

Для расширенных действий бонус максимум 0.0045R применяется **после** их Expected/CVaR/source/stress допуска. Blocked действие остаётся blocked. HOLD сохраняется, автоматические ордера не создаются, стоп не расширяется, объём не увеличивается. Price-преобразования не дают дополнительную независимую семью evidence.

## Проверка на истории

Общие временные границы 40/55/70/80% фиксируются по 15m anchor timeline до выбора горизонта и фильтрации conditional direction. Три ранние validation части выбирают горизонт; последние 20% времени не используются для выбора. Training outcomes должны завершиться раньше начала проверки с embargo 5 минут. Поздняя validation не использует outcomes после начала финального теста. Для личного working допуска нужен положительный средний proper-score gain на ранней validation и положительный gain на нетронутом финальном тесте. Все три validation и финальных блока должны иметь пригодные конечные оценки. Если положительны минимум две из трёх частей на обоих этапах, это STABLE_HISTORICAL; иначе LIMITED_HISTORICAL с половиной прежнего веса, дополнительно уменьшенного существующей поправкой на число положительных блоков, размер теста и возраст данных. Ограниченный допуск не называется устойчивым или формально доказанным edge. Prospective ожидание не требуется для ручного рабочего использования. Отрицательный или нулевой средний результат любого из двух этапов не допускается. После проверки выбранные головы переобучаются на уже завершившихся наблюдениях.

`docs/verification/mathematical_edge_historical_working.json` содержит фактический GitHub Actions run на сохранённых исторических provider-барах и завершённых direct минутных барах. Допуск проверяется по каждой голове; положительный средний результат обоих OOS этапов без устойчивости допускает только ограниченный исторический вклад, а не устойчивый уровень. Proper-score в mbit/event измеряет качество вероятностного прогноза, **не R, деньги или net PnL**.

Экспорт production read-only и ограничен десятью инструментами: cached Yahoo 5m плюс retained **direct** minute bars. Бары `derived`, включая `yahoo_1m_offset_adjusted`, исключаются из обучения: неизвестный исторический offset не восстанавливается предположением. Минуты, впервые сохранённые до их завершения (created_ts < bar_end_ts), также исключаются. Provider, ticker, source semantics, counts direct/derived и исключения сохраняются в отчёте. Эти цены могут быть reference proxies, не фактическими исполнениями у брокера. Runtime intraday Yahoo признаки также явно помечены proxy/current-basis.

## Что воспроизведено из архива

SHA-256 компактного и полного ZIP проверены. Все 167 строк FX golden расчёта совпали: 8 veto, +0.07244231955423992 **gross bp/base**. В raw events найден точный H2 input `g1s_evidence_v3.gex.dynamics.force_score.slope`; совпадение 167/167, ошибка 0. Восстановлены 60 строк Phi_G, fingerprint, mean и sample SD. Phi_G и dot-GEX — разные координаты.

Параметры старого FX H2 KEEP/VETO сохранены: interval [-0.00067862, -0.00004046], theta=1.38343, threshold=.38. GEX не переносится с FX на индексы/металлы: их архивный incremental audit не дал убедительной поддержки. Применение старого theta к новой Price голове публикуется только как диагностический counterfactual, вес 0. Старый veto входа не становится командой закрыть существующую позицию. Старые Price decoder coefficients отсутствуют; новые модели не называются их точной копией.

## Наблюдаемость и воспроизведение

В обычном и deterministic AI-разборе есть раздел «МАТЕМАТИЧЕСКИЙ EDGE»: conditional probabilities, роли, веса базовых/расширенных действий, score вне обучения, model hash, source, причины нулевого веса и выбор до gate с/без mathematical edge. Данные сохраняются при compaction; финальное решение по-прежнему выбирают gate и арбитр.

`GET /api/research/mathematical-edge` возвращает компактный frozen отчёт по всем инструментам без fitting, сетевой загрузки или сканирования базы в HTTP. Коэффициенты не нужны этому endpoint и исключены из ответа. Фitting выполняется на GitHub runner; публикация атомарная для точного SHA. PR run ничего в production не записывает.

Локальная проверка архива: `python -m scripts.verify_mathematical_edge_archive --raw-dir <extracted>/90_RAW_SOURCE_DATA --output archive-audit.json` (optional pandas/pyarrow). Проверка моделей: `python -m scripts.run_mathematical_edge --sources mathematical_sources.json --output mathematical_edge_latest.json`. Raw источники не коммитятся и не загружаются в терминал вместе с кодом.

Интеграционные проверки проходят Engine→snapshot→отчёт: математический вес действительно присутствует в ранжировании и отчёте, исходные Expected/CVaR не меняются, hard CVaR и допуски расширенных действий сохраняются.
