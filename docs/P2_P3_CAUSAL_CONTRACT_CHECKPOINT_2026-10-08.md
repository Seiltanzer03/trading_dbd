## Выполненные задачи

1. Воспроизведён дефект P2: 60 разных сделок с одним macro release ID могли
   образовать train и два OOS блока и выпустить `OOS_VALIDATED` модель.
   Тренер теперь соединяет сделки, имеющие общий явный release ID, включая
   `release:` dependency group и release proofs составных event features.
   Связи транзитивны: несколько релизов в одной строке соединяют зависимые
   группы. Generic provider/source ID не является release ID.
2. Разделение и purge работают на целых группах связанных сделок/релизов.
   Сохраняются существующие минимумы 40 независимых групп, 20 training и два
   блока по 10, временной purge, проверка издержек и положительный OOS MSE gain.
   `group_count` теперь означает независимые группы; `trade_group_count`
   отдельно показывает число сделок. Group policy сохранён в конфигурации,
   диагностике и новом artifact. Только реально используемые признаки
   определяют зависимости. Общая цепочка shared-release proofs может
   консервативно уменьшить число независимых групп; это явное ограничение.
3. Воспроизведён дефект P3: отклонённый calendar packet стирал ранее принятый
   session context, хотя признаки оставались допущенными. Default context
   теперь задаётся один раз; принятый context следует самому свежему календарю
   по тому же observed clock, который выбирает владельца session features.
   Отказы остальных packets сохраняются. Правило равных timestamps не менялось.

Шесть регрессий были red на исходном коде; дополнительная регрессия unused
provenance была red на промежуточной реализации. Профиль training/adapters/
reaction/novelty/pipeline/dataset/history: **685 passed**, 5.98s. Production
изменён только после обязательного final-revision CI и штатной приёмки; их
фактическое evidence записывается в PR, а не подразумевается этим checkpoint.
