# EDE: согласованное потоковое чтение инвентаризации

Граница следующего блока после PR455: исправить один подтверждённый дефект
чтения истории. Production inventory38217327690 превысила37минут SSH-команды.
Её отдельное read-only соединение не имело признака согласованного снимка,
поэтому adapter вызывал fetchall для всех исходных frozen JSON одного горизонта.
Размер live SQLite в соседнем audit —17.9GB. Это подтверждает путь неограниченной
загрузки, но ещё не доказывает единственную причину production timeout.

Изменение ограничено двум существующим слоям: dedicated inventory connection
открывает read transaction, adapter разрешает fetchmany32 для этого соединения
только пока транзакция активна. Count, feature audit и все горизонты видят одну
версию данных даже при параллельной WAL-записи. Общий live engine сохраняет
атомарный fetchall: его same-connection commits не смешиваются с итерацией.
Live DB не называется immutable и не подменяет подтверждённый off-host snapshot.

Достигнутая локальная граница: два дефекта сначала воспроизведены RED; финальные
69проверок passed (2.33s). Проверены145записей без потери порядка, пакет≤32,
согласованность при concurrent writer, запрет записи, fallback без активной
транзакции, равенство derived rows/fingerprint и прежняя атомарность live engine.
Полный CI, независимый review, выпуск и фактическая длительность production
inventory остаются обязательными. Feature thresholds, причинные clocks, веса,
evidence admission и authority не меняются. SQLite replication stall является
отдельным незакрытым ограничением; тайм-ауты здесь не увеличиваются.
