# SEILTANZER TERMINAL

Локальный веб-дашборд поддержки решений для дискреционного трейдера, торгующего
price-action сетапы (FVG / sweep / AMD) на индексах, металлах и валютах через
проп-фирмы. В каждый момент открытой сделки терминал показывает **вероятность
дохождения до тейка раньше стопа**, обогащённую данными опционного рынка, в
«бумажном» визуальном стиле квант-терминала.

> Это **инструмент поддержки решений, не сигнальный сервис**. Всё, что показано
> на экране, выводимо из реально полученных данных. Каждое число имеет tooltip
> «как посчитано» (формула + источник). Нет данных — панель показывает честное
> «нет данных», а не последнее/выдуманное значение.

## Запуск

```bash
pip install -e .
python -m seiltanzer            # терминал на http://127.0.0.1:8790
python -m seiltanzer --demo     # демо-режим: синтетический поток (бейдж DEMO)
```

Опции: `--host`, `--port 8790`, `--data-dir .` (куда класть `trades.db` /
`cache.db`).

Требуется Python 3.11+. Основные зависимости: FastAPI, uvicorn, numpy, pandas,
yfinance. Данные: `yfinance` — котировки и delayed-цепочки ETF-прокси
(QQQ→NAS100, SPY→SP500, DIA→US30, GLD→XAU), индексы `^VIX` / `^GVZ` / `^V1X`.
Кэш пишется на диск в sqlite.

### Тестирование без локальной установки

Не хотите ставить Python на рабочий компьютер — есть два способа проверить всё
прямо в браузере:

- **GitHub Codespaces (запуск приложения).** Откройте репозиторий на GitHub →
  кнопка **Code** → вкладка **Codespaces** → **Create codespace on main**.
  Среда поднимется в браузере и сама установит зависимости (`.devcontainer`).
  В терминале Codespace выполните `python -m seiltanzer --demo` (демо-поток) или
  `python -m seiltanzer` (живые данные — в Codespaces есть интернет). Порт 8790
  пробросится автоматически, откроется вкладка с терминалом.
- **GitHub Actions (проверка тестов).** На каждый push во вкладке **Actions**
  прогоняются все тесты (`pytest`). Зелёная галочка = весь набор тестов прошёл — видно на
  GitHub без запуска чего-либо у себя.

### Деплой на свой сервер (VPS)

На чистом Ubuntu/Debian-сервере под root — одна команда (ставит Python, зависимости,
swap 1 ГБ, systemd-сервис с автозапуском и рестартом):

```bash
curl -fsSL https://raw.githubusercontent.com/Seiltanzer03/trading_dbd/main/deploy/install.sh | bash
```

Затем откройте `http://ВАШ_IP:8790`. Управление: `systemctl restart seiltanzer`,
логи `journalctl -u seiltanzer -f`. Порт/режим: `PORT=8080 MODE=demo curl … | bash`
(режимы: `stream` — живой WS-стрим цены, по умолч.; `live` — только
REST-котировки со статусом delayed/indicative; `demo`).

**750 МБ RAM достаточно** (скрипт добавляет swap для запаса). **Безопасность:** у
приложения нет входа/пароля — кто угодно с IP:порт получит доступ к терминалу и
журналу. Ограничьте порт облачным фаерволом провайдера на ваш IP, либо держите
доступ только через SSH-туннель (`ssh -L 8790:localhost:8790 root@IP` и открывать
`http://localhost:8790`).

#### Обновление сервера — три способа

1. **Автодеплой (GitHub Actions).** Воркфлоу `.github/workflows/deploy.yml` при
   каждом пуше в `main` (или по кнопке *Actions → deploy → Run workflow*) гоняет
   тесты и сам заходит на сервер по SSH: `git reset --hard origin/main` + рестарт.
   Нужен один секрет репозитория `SSH_PASSWORD` (Settings → Secrets → Actions).
2. **Из локальной папки, без GitHub** (`deploy/local_deploy.py`). Заливает текущую
   папку на сервер по SSH/SFTP и рестартит сервис — для агента/машины, у которой
   есть только папка проекта и сеть до сервера. Настройка: скопировать
   `deploy/server.env.example` → `deploy/server.env`, вписать хост/логин/пароль,
   затем `pip install paramiko && python deploy/local_deploy.py`. Папка `data/`
   на сервере не трогается; заливаются только изменённые файлы.
3. **Вручную одной командой** — тот же `install.sh` (делает `git reset --hard
   origin/main` + рестарт) в веб-консоли VPS.

### Живой стрим цены (бесплатно, опция)

```bash
python -m seiltanzer --stream    # + живой WebSocket-стрим цены Yahoo
```

`--stream` открывает бесплатный WebSocket Yahoo (`wss://streamer.finance.yahoo.com`,
без API-ключа) и тянет **тики инструмента и option-proxy** — луч цены, r,
moneyness, P, конус, веер и гряда двигаются в реальном времени. При сбое стрима
автоматически используется REST. Нужен `pip install websockets` (в зависимостях).

**Что стримится, а что нет (честно):** полная **опционная цепочка/IV** бесплатно
не стримится и может быть задержана примерно на 15 минут. Она задаёт форму,
implied move, BL-tail, skew и term structure. Между снимками текущие тики
инструмента и ETF-proxy пересчитывают moneyness и first-passage сценарий, не
изображая новые опционные котировки. Тиковые опционы требуют платного источника.

### Боевой режим без заглушек · самопроверка данных

`python -m seiltanzer` (без `--demo`) работает **только на реальных бесплатных
данных Yahoo** — никакой синтетики: весь синтетический код (`DemoMarket`,
`synth_chain`, засев снапшотов) жёстко изолирован за флагом `--demo` и в боевом
режиме вообще не создаётся. Если источник не ответил — панель показывает честное
«нет данных», а не подставляет фейк.

Проверить, что реально доступно в вашей сети (прогоняет те же боевые фиды):

```bash
python -m seiltanzer --check
```

Печатает по каждому инструменту: цена, дневки, опционная цепочка (число страйков,
implied move, скью, term) и индексы волатильности — с пометкой `live` только для
stream-тика, `delayed` для REST/опционного снимка, `ok` для загруженной истории
или `no_data` (источник не ответил, без подстановки). Опционные
цепочки надёжны для QQQ/SPY/DIA/GLD/SLV; прокси EWG/EWU/FXE/FXC — тонкие (⚠).

### Проверка честного «нет данных»

Выключите интернет (или запустите там, где Yahoo недоступен) — все панели
перейдут в состояние «нет данных» с текстом причины, а UI останется живым.
Демо-режим (`--demo`) синтезирует все потоки и помечает бейджем DEMO каждую
панель — для проверки анимаций без сети.

## Как работать с сигналом (не инструмент ради инструмента)

Терминал сводит всё в **один вердикт сделки** в шапке — крупный сигнал + действие:

1. **OPTION EDGE vs EV=0** — опционно-якорная P(тейк раньше стопа) минус
   минимальная P безубыточности при фактических стопе и тейке. Геометрия
   стоп/профит задаёт только порог, но не саму вероятность.
2. **Вердикт** (СИЛЬНЫЙ ПЕРЕВЕС / ПЕРЕВЕС / НЕЙТРАЛЬНО / ОСТОРОЖНО / НЕ ВХОДИТЬ) —
   синтез option edge, точных фильтров и фазы. GEX, skew и бесплатные 15m
   vol-метрики видны как контекст, но не получают скрытого решающего веса.
3. **Факторы-чипы** показывают источник, задержку и применимость каждого слоя.

Практический цикл: нашли сетап на графике → смотрите вердикт: если **НЕ ВХОДИТЬ**
(фильтр блокирует) — пропуск; если **ПЕРЕВЕС** и край положительный — вход по
плану; в позиции следите, сохраняется ли option edge по живой moneyness. OI/GEX
можно использовать как вторичный контекст уровней, но не как доказанный flow.

## Панели

1. **Шапка «аккаунт»** — конфигурация, активный сетап (№ и имя), фаза
   (1ph/2ph/funded), баланс % и строка динамической матрицы риска (риск %,
   целевой RR × ATR-множитель, режим). Справа: статусы фидов (цена / цепочка /
   VIX), UTC-часы, кнопки сделки. Под шапкой — **вердикт сделки** (синтез края,
   фильтров, скью/term-контекста и фазы) с рекомендованным действием.
2. **Строка «Состояние / Перспектива»** — где сделка сейчас и куда клонит, одним
   взглядом: текущий **r**, дистанции до тейка и стопа (в **R** и в **ATR** —
   «сколько обычных свечей» до цели), **P(тейк раньше стопа)** с интервалом,
   **option edge** и как он сдвинулся с момента входа (`edge_at_open`), и одна
   сжатая формулировка действия.
3. **Probability Lattice** — option-anchored barrier distribution в R. Implied
   move задаёт ширину, BL-плотность — terminal tail/forward, skew — асимметрию,
   term structure — раскрытие во времени. Неразрешённые к экспирации пути
   якорятся BL tail-ratio. Пунктир — исторический control, не источник edge.
   Слева: **P OPTIONS**, **OPTION EDGE vs EV=0**, r, опционный EV hold и
   справочный path-control лестницы. Если option anchor отсутствует, визуальный
   fallback остаётся, но edge выключается.
4. **Strike Landscape** — гряда risk-neutral плотностей (Бриден–Литценбергер)
   из снапшотов реальных опционных цепочек; нижняя жирная — актуальная. Поверх —
   **живая красная контрольная кривая** и **профиль open interest**
   снизу. Вертикали: вход / стоп / тейк / GEX. Слева, кроме implied move / скью /
   term: **max OI** — крупнейший опционный интерес по коллам/путам с расстоянием
   в %. Это контекст концентрации, не доказанная стена и не наблюдаемая дилерская
   позиция. Выноска: terminal P(за тейк/стоп) рядом с first-passage P.
5. **Probability Cone (3D)** — **настоящий WebGL-3D** (Plotly gl3d, вендорится
   локально): сцену можно **вращать мышкой, зумить колесом, наводить курсор** для
   точных значений. Поверхность = плотность вероятности исхода (PDF surface): ось
   R (стоп · 0 · тейк), ось **времени** (к развязке), высота — плотность живых
   (ещё не поглощённых) путей. Две **стены-барьера** (Mesh3d): красная (стоп) и
   зелёная (тейк) — их высота по времени = накопленная вероятность дойти, у дальней
   грани = **P(стоп) / P(тейк)** (те же числа, что и шапка-P). Оранжевый луч —
   текущая цена (r); тёмный пунктир на дальней грани — терминальная плотность
   **рынка** (где рынок ждёт цену на экспирации). Ось времени использует срок
   ближайшей экспирации. Данные сетки — с бэкенда (`prob.rn_cone`).
6. **Веер вероятности 2D** — читаемый срез того же конуса с теми же барьерами,
   сроком и option anchor; это не отдельная конфликтующая модель.
7. **IV Surface (3D)** — delayed IV-snapshot нескольких экспираций на общей
   moneyness-сетке. ATM двигается живым тиком proxy. Значения IV не маркируются
   как live; tail-skew показывается как контекст текущей moneyness.
8. **Карта уровней** — коридор цены вокруг позиции: FVG-зоны (введённые вручную),
   GEX-уровни, implied move ±1σ до конца сессии, VWAP дня, вход/стоп/тейк.
9. **Фильтры и лестница фиксации** — чипы VIX / GVZ / DV1X / ATR-фаза /
   Теханализ (PASS / BLOCK / MANUAL) и 6 рубежей лестницы с БУ после 1.5R.
10. **Журнал** — таблица сделок и редкие снимки опционных прогнозов. Калибровка
    first-passage проверяется out-of-sample по первому прогнозу сделки: Brier,
    log loss и bins; ручные/частичные выходы без barrier-исхода цензурируются.
    Статистика сетапов остаётся контрольным слоем.

## Математическое ядро (`seiltanzer/core/`)

**`prob.py` — вероятности и Монте-Карло**

- **First-passage.** Путь сделки в R-координатах: `dX = μ dt + σ dW`, стоп −1,
  тейк +T. Функция масштаба `s(x)=exp(−2μx/σ²)`;
  `P(тейк раньше стопа | x) = (s(x)−s(−1)) / (s(T)−s(−1))`
  (в коде — численно устойчивая форма через `expm1`).
- **Калибровка μ по winrate** сохранена для пунктирной контрольной линии и
  исследования лестницы; она не создаёт option edge.
- **Option-anchored cone.** Barrier MC использует implied move, BL terminal
  tail/forward, skew и term structure. Неразрешённая масса распределяется по
  BL tail-ratio, а не по формуле расстояний. Skew-шум аналитически центрирован
  и нормирован, поэтому асимметрия хвостов не создаёт скрытый ложный дрейф.
  Если стоп или тейк лежит вне доступной сетки страйков, option edge выключается:
  нулевая масса за границей бесплатной цепочки не принимается за вероятность.
  То же происходит, если суммарная BL-масса за двумя барьерами <0.5%: отношение
  столь малых хвостов слишком чувствительно к одному плохому бесплатному mid.
- **Монте-Карло** остатка сделки с поглощением на −1 и T (поправка броуновского
  моста устраняет смещение дискретизации): терминальное распределение,
  вероятности по горизонтам, EV «холд» vs EV «лестница фиксации».

**`options.py` — опционная математика**

- **Implied move** из ATM straddle ближайшей экспирации → `σ_implied` годовая.
- **Опционная поправка волы**: σ процесса масштабируется отношением
  `σ_implied / σ_baseline` (baseline — реализованная вола за 20 дней). В сжатом
  рынке далёкий тейк честно теряет вероятность на горизонте, в разогнанном —
  набирает. Источник σ_implied по приоритету: цепочка ETF-прокси
  (QQQ/SPY/DIA/GLD/**SLV**) → иначе профильный индекс волы (**^EVZ** для EURUSD)
  → иначе поправка не применяется, и это явно пишется в UI.
- **Risk-neutral density** (Бриден–Литценбергер): `q(K) ≈ e^{rT} d²C/dK²`
  численно, сглаживание локальной квадратичной регрессией, обрезка отрицательных.
- **Proxy mapping:** direct `Y=S_y·K/S_x`; inverse `Y=S_y·S_x/K` с Jacobian
  плотности. Текущие `S_y/S_x` обновляются тиками между delayed-снимками.
- **GEX-уровни** (помечены как эвристика): `GEX(K)=Σ γ(K)·OI·100·S²·0.01`,
  коллы +, путы −; zero-gamma flip и 3 крупнейших уровня. Допущение о
  позиционировании дилеров непроверяемо — только контекст.

**`risk.py` — риск-менеджмент (главы 2.1 / 2.6 / 2.9)**

- Динамическая матрица риска и целевого RR (формулы перенесены из
  Excel-калькулятора), поправка фазы проп-фирмы (1ph +2%, 2ph +1%).
- ATR-фаза `ratio = ATR(5)/ATR(20)`: шок (k=0.5), импульс (k=1.2), флэт (k=0.7),
  норма (k=1.0) — корректирует отображаемый целевой RR.
- Формула эффективности сетапа `2α/(α+β)` с интерпретацией.

## API

- `GET /api/state` — полное состояние (первый рендер): тик, гряда, журнал, сетапы.
- `WS /ws` — тики: цена, r, p, [p_lo, p_hi], фаза ATR, фильтры, МК, лестница, уровни.
- `GET /api/chain[?ticker=QQQ]` — гряда BL-плотностей + GEX + implied move (кэш ~10 мин).
- `POST /api/trade`, `POST /api/trade/close`, `POST /api/trade/zones` — жизненный
  цикл сделки.
- `GET /api/journal`, `POST /api/journal` (бэкфилл), `GET /api/journal.csv`.
- `GET /api/setups` — встроенная таблица 16 сетапов (winrate, n, RR) + журнальная
  статистика.
- `GET /api/diagnostics` — реальный ценовой ряд, basis, proxy transform, возраст
  chain и decision weight каждого визуального слоя.
- `GET /api/validation` — Brier/log loss/calibration option-прогнозов.
- `POST /api/account` — название / фаза / начальный капитал / баланс.
